# DocuRAG

DocuRAG is a local-first document question-answering application. Users create an account, upload documents, wait for background indexing, and ask questions against selected indexed documents. Answers are generated by Ollama and include the retrieved document and chunk as source metadata.

## Features

- Cookie-based JWT authentication
- Per-user document ownership
- TXT, PDF, and DOCX text extraction
- Asynchronous extraction, chunking, and embedding
- Local embeddings with Ollama `nomic-embed-text`
- Local answer generation with Ollama `llama3.1`
- Application-level cosine-similarity retrieval
- Conversation history and source citations
- Document status and download tracking

## Architecture

The application is an Express server with EJS views and a MongoDB persistence layer.

```text
Browser -> Express routes/controllers -> JWT authentication
			 -> MongoDB (users, files, chunks, conversations)
			 -> Ollama embeddings during indexing
			 -> Ollama generation during chat
```

Important modules:

- `src/app.js`: Express middleware, views, and route registration.
- `src/server.js`: MongoDB connection and HTTP server startup.
- `src/controllers/`: request validation and response handling.
- `src/services/document.service.js`: background indexing lifecycle.
- `src/services/extraction.service.js`: TXT, PDF, and DOCX extraction.
- `src/services/chunking.service.js`: normalized overlapping text chunks.
- `src/services/embedding.service.js`: Ollama embedding client.
- `src/services/retrieval.service.js`: owner-scoped cosine-similarity retrieval.
- `src/services/rag.service.js`: prompt construction and Ollama answer generation.
- `src/models/`: Mongoose models for users, files, chunks, and conversations.
- `views/`: server-rendered dashboard, document, authentication, and chat pages.

## Requirements

- Node.js 20 or newer
- npm
- MongoDB 7 or a compatible MongoDB deployment
- Ollama 0.32 or newer
- At least 6 GB of available disk space for the default chat model

## Local setup

Install dependencies:

```bash
npm ci
cp .env.example .env
```

Set a private random `JWT_SECRET` in `.env`, for example:

```bash
openssl rand -hex 32
```

Start MongoDB with Docker:

```bash
docker run -d --name docurag-mongodb \
	-p 27017:27017 \
	-v docurag-mongo-data:/data/db \
	mongo:7
```

For an existing container, use `docker start docurag-mongodb`.

Start Ollama and download the required models:

```bash
ollama serve
ollama pull nomic-embed-text
ollama pull llama3.1
```

Ollama may already be running as a system service. Starting a second server on port `11434` reports `EADDRINUSE`; check it instead:

```bash
curl http://127.0.0.1:11434/api/version
```

Start DocuRAG:

```bash
npm start
```

Open <http://127.0.0.1:3000>, register a user, upload a document, and open RAG Chat after its status becomes `INDEXED`.

Development mode uses Nodemon:

```bash
npm run devStart
```

Only one application process can use port `3000`. To find and stop an existing listener:

```bash
kill $(lsof -tiTCP:3000 -sTCP:LISTEN)
```

## Environment variables

| Variable | Default | Description |
| --- | --- | --- |
| `DATABASE_URL` | `mongodb://127.0.0.1:27017/fileSharing` | MongoDB connection string |
| `PORT` | `3000` | HTTP listening port |
| `JWT_SECRET` | development fallback | Secret used to sign authentication cookies; set a strong value outside local development |
| `JWT_EXPIRES_IN` | `1d` | JWT lifetime accepted by `jsonwebtoken` |
| `AI_BASE_URL` | `http://127.0.0.1:11434` | Ollama API base URL |
| `AI_EMBEDDING_MODEL` | `nomic-embed-text` | Ollama embedding model |
| `AI_CHAT_MODEL` | `llama3.1` | Ollama generation model |
| `NODE_ENV` | unset | Set to `production` to enable secure cookies |

`.env` is local configuration and must not be committed. Use `.env.example` as the shareable template.

## Supported documents and limits

- Plain text: `.txt` or `text/plain`
- PDF: `.pdf` or `application/pdf`
- Microsoft Word: `.docx` or the official DOCX MIME type
- Upload limit: 20 MiB per file
- Text chunks: 1,200 characters with a 200-character overlap by default

Statuses are `UPLOADED`, `PROCESSING`, `INDEXED`, and `FAILED`. Unknown file types currently use a UTF-8 fallback; upload supported text-based formats for reliable results.

## Routes

| Method | Route | Purpose |
| --- | --- | --- |
| `GET` | `/register` | Registration page |
| `POST` | `/auth/register` | Create an account |
| `GET` | `/login` | Login page |
| `POST` | `/auth/login` | Create an authentication cookie |
| `POST` | `/auth/logout` | Clear the authentication cookie |
| `GET` | `/` | Owned-document dashboard |
| `POST` | `/upload` | Upload and queue a document |
| `GET` | `/documents` | List owned documents |
| `GET` | `/documents/:id` | View owned document metadata |
| `GET` | `/documents/:id/download` | Download an owned document |
| `GET` | `/chat` | RAG chat page |
| `GET` | `/conversations` | Conversation list |
| `POST` | `/api/rag/ask` | Generate an answer from selected owned documents |

The RAG request body is:

```json
{
	"question": "What does this document say?",
	"documentIds": ["<indexed document id>"],
	"conversationId": "<optional conversation id>"
}
```

A successful response contains `conversationId`, `answer`, and `sources`. Each source includes the document ID, original filename, chunk index, and similarity score. Document IDs and conversations are checked against the authenticated user.

## Testing

The project uses Node's built-in test runner and deterministic tests do not require MongoDB or model downloads:

```bash
npm test
npm run lint
```

Tests cover text normalization and chunking, invalid chunk settings, cosine similarity edge cases, and prompt history/context construction. The live Ollama and MongoDB path has also been validated with authenticated upload, indexing, retrieval, generated answer, citation, and conversation persistence.

CI runs on Node 20 with a MongoDB 7 service container. AI calls should remain mocked in future HTTP integration tests so CI does not download local models.

## Troubleshooting

Check MongoDB:

```bash
docker ps --filter name=docurag-mongodb
docker start docurag-mongodb
```

Check Ollama:

```bash
curl http://127.0.0.1:11434/api/version
ollama list
```

A `302` response from `http://127.0.0.1:3000/` is expected without a login cookie. `EADDRINUSE` on port `3000` means another application process is already running. The current worker is in-process, so queued jobs are lost on restart; inspect `processingError` or re-upload documents stuck in processing.

## Security and limitations

Use a long random `JWT_SECRET` and HTTPS in production. Cookies are HTTP-only and secure when `NODE_ENV=production`; documents and chunks are scoped by owner ID.

Before public deployment, add CSRF protection, login and AI rate limiting, upload quotas, malware scanning, durable background jobs, request timeouts, stronger upload signature validation, and production object storage. Retrieval currently loads a user's chunks into Node for cosine scoring, and citations identify chunks rather than PDF pages.
